The component

Where it started: the basic menu

What it was

A compact list of actions for a single record, opened from a ⋮ trigger. It was fine for basic selections in data grid rows, card footers and panel headers.

How it behaves

Opens on click, Enter, Space or ↓. Arrow keys move between items. It closes when you pick an item, press Esc or click outside.

The need

One product needed a lot more

Time's user profile had to let people switch tenants, view the app as another user, change language and manage profile settings, all from one menu.

It needed

  • A header, and nested lists that slide back and forth in the same panel
  • Eyebrow descriptions, and toggles for on/off settings
  • Search for long lists of tenants and users

It still shared the same size, states, colours and trigger as the basic menu.

The tension

Expand the component, or is it too bespoke?

Expanding a core component for one product's user profile risks bloating it with one-off features. The concern was fair: was this a pattern, or just Time's menu?

Then a second product

Around the same time, Billstream needed the same kind of user menu: a header, a user row that slides into a searchable "switch user" list, and information rows with descriptions.

Two products with the same need made it a pattern. That was the case for expanding the menu.

The problem

Every slightly different menu became a new one

Researching Time's and Billstream's needs meant looking at how menus were really being used across our products.

That's where the bigger problem surfaced: teams were coding or designing a new menu any time they needed something a little more custom.

Two user profiles weren't the whole story. The menu needed much more flexibility to allow for custom patterns.

“A little more custom” meant a whole new menu.

A team needs a slightly different menu ↓ The basic menu can't flex to fit ↓ A new menu is designed and coded

Making the case

Same patterns, shared properties

  • Compared the two menus: what they had in common and the navigation patterns they shared
  • Mapped the properties each one needed onto a single component
  • Tested the component with design system designers and product designers
  • Collected feedback on how the component was used in Figma

The build

Extend the item, then add slots

With engineering, we decided to build it by first extending the menu item sub-component.

  • Menu item: a right icon as a boolean property, or a slot for a toggle child component
  • Menu container: slots for a search bar or other custom content
  • Header and footer: turned on by booleans, with slots for headings, buttons or other content

Properties

Accessibility

Every path works from the keyboard

Nesting, search and toggles add new ways to move through a menu. I worked with designers and engineers to make sure keyboard navigation made sense and stayed accessible at every level.

  • Arrow keys move through items using a shared keyboard navigation manager. Focus wraps by default, and there's a tab-only mode
  • → or Enter slides into a nested list, and ← or Esc slides back to the row that opened it
  • Toggles are menuitemcheckbox rows and never close the menu
  • Focus returns to the trigger only after keyboard activation, never after a mouse click

Contribution

Office hours with product engineers

During development I ran office hours with the product engineers. I demoed the component, learned which click events they would pass into the menu, and gathered their feedback.

What shaped the API

  • One udsClick event with the item's value, label and state
  • A separate udsToggleChange event, so toggles don't need extra wiring

Impact

One menu instead of many

Teams had been building a new menu component every time they needed a slightly different configuration. Now they only need this one.

  • Product teams retired their custom menu components
  • The same component serves the simplest row actions and the most complex user profile
  • Designers and teams build their own menu patterns while staying aligned with UX principles, accessibility and visual design
